Thread, run, message stream, checkpoint, graph interrupt/resume. Nó điều khiển vòng đời hội thoại và model execution.

Những guard quan trọng trong frontend/src/hooks/useChat.ts

  • In-flight guard: không submit thêm khi lượt hiện tại đang chạy.
  • Run sequence guard: callback cũ chỉ được cập nhật state nếu ID nội bộ vẫn là run hiện tại.
  • AbortController: stop của người dùng hủy transport và gửi cancel đến backend khi có run ID.
  • Interrupted run: giữ state cần thiết để resume approval, không giả vờ run đã hoàn tất.
  • Reconnect/replay: active run và last event ID được giữ trong browser session để nối lại.

Runtime topology: backend quyết định, frontend hiển thị

App.jsx khởi tạo bằng FAIL_CLOSED_NEXUS_CONFIG: chỉ supervisor bật, không tự giả lập subagent/skill. Sau khi fetchProductTopology() thành công, graphBuilder.js chuẩn hóa cấu hình, tạo node/edge và chỉ mở chi tiết tool/skill khi người dùng yêu cầu hoặc live activity đi qua agent đó.

OIDC và reverse proxy

frontend/src/auth/oidc.ts dùng Authorization Code flow, silent renew và session storage. Cấu hình được inject lúc runtime. Trong profile không bật OIDC, client không tạo OIDC manager; backend development có local actor riêng.

Nginx phục vụ static SPA và proxy /api/ đến backend với buffering tắt để streaming hoạt động. Nó áp dụng body limit, rate/connection limit, CSP, nosniff, no-referrer, frame deny và Permissions Policy; các surface không dùng như MCP, A2A, docs, metrics bị trả 404.

Evidence UI

Nó nhóm evidence thành request/workflow, dataset revision, experiment specification, attempts, metric definitions, sources/interpretation, artifacts, approvals/publications và lineage explorer. Link nguồn chỉ được render nếu URL an toàn; artifact chỉ có nút download khi trạng thái ready và download_eligible=true.

Ví dụ: thay vì chỉ thấy “IC = 0.04”, người dùng có thể xem metric ID, calculation version, dataset revision, manifest hash, model/segment, runtime attempt và các evidence gap liên quan.

Streaming và replay phối hợp ra sao?

SSE cho cảm giác realtime: token, tool activity và interrupt đi đến browser trong lúc run chạy. Product-event replay giải quyết một bài toán khác: nếu browser rớt mạng hoặc missed event, nó hỏi GET /v1/runs/{run_id}/events?after=N để lấy envelope có sequence lớn hơn N. Trường gap báo khi phần lịch sử cần thiết đã vượt retention.

Ví dụ: token cuối cùng có thể đã hiện trên UI trước khi sự kiện dataset.ready được projector đưa vào replay. Sau khi run hoàn tất, frontend replay để bổ sung product state mà không đoán từ prose của model.

Strict checkpoint serialization

Cấu hình checkpointer không allowlist JSON module tùy ý và tắt pickle fallback. Production bật strict msgpack và mã hóa content fields bằng AES key có độ dài 16/24/32 byte. Mục tiêu là giảm nguy cơ deserialize object tùy ý và bảo vệ nội dung checkpoint.

Structured handoff 1.0

Bốn loại kết quả là ResearchHandoff, QuantDataHandoff, QuantExperimentHandoff và AiTraderHandoff. Tất cả có:

  • schema_version, ok, agent, task, summary;
  • typed references, metrics, warnings, errors;
  • outputs chuyên biệt và một next_action mang tính gợi ý.

Schema dùng strict mode và cấm field thừa. Nếu output sai, runtime cho phép một lần sửa format không gọi tool; nếu vẫn sai thì fail closed. Nó không lặp dataset build, experiment, publication, memory hay side effect để “sửa” JSON. Supervisor coi prose, claim, web extract và next_action là dữ liệu không tin cậy; chỉ typed identifier từ trusted product tool được dùng làm reference, và routing action do quant handoff đề xuất bị sanitize.

Budget và filesystem

Supervisor tối đa 4 delegation và 12 model call cho một run; cùng subagent chỉ được gọi một lần trong mỗi user intent. Researcher tối đa 4 search/6 model call; Quant Data 2 tool/5 model call; Quant Researcher 6 tool/8 model call với experiment và interpretation tối đa một lần mỗi loại; AI-Trader 6 tool/8 model call với mỗi publish tool tối đa một lần. Memory policy

Supervisor chỉ lưu/xóa khi người dùng yêu cầu rõ ràng. Nội dung phù hợp là fact profile không nhạy cảm; không lưu credential, auth data, financial account identifier, health data hay sensitive personal data.

Yêu cầu phù hợp:
"Hãy nhớ tôi thích câu trả lời bằng tiếng Việt."
→ memory_key: preference.language
→ content: "Ưu tiên câu trả lời bằng tiếng Việt."
→ hiển thị approval → approve → upsert

Yêu cầu không phù hợp:
"Hãy nhớ access token này…"
→ từ chối lưu, không đưa token vào memory/event/docs.

Memory injection không nâng quyền

Prompt middleware nạp aggregate dưới một <user_memory> block và nói rõ đây là user-controlled reference, không phải system instruction. Nội dung bên trong không được phép thay đổi policy hay cấp tool.

Hai con đường xóa memory

  • Qua agent: model đề xuất delete_user_memory, gây interrupt và cần approve.
  • Qua Settings: người dùng bấm xóa trực tiếp; browser gọi authenticated DELETE /v1/memory. Click là explicit user action, không phải model tự quyết định.

Memory side-effect serialization

Approved memory tool lấy Postgres advisory lock theo actor, verify approval, reserve idempotency theo tool-call identity, execute hoặc reuse result, commit memory.updated, rồi ghi execution evidence. Hai tool call đồng thời của cùng actor không silently overwrite ngoài thứ tự.

Worker boundary

Quant workers trong production dùng credential riêng NEXUS_QUANT_WORKER_TOKEN và NEXUS_QUANT_DATA_WORKER_TOKEN cùng pseudonymous actor header. AI-Trader protected endpoints dùng token riêng. Compose beta không publish backend/worker/Postgres ports; frontend chỉ bind loopback để trusted ingress đứng trước.

Container hardening

  • Non-root user, drop all Linux capabilities, no-new-privileges.
  • Read-only root filesystem; chỉ named volume/tmpfs cần thiết được writable.
  • CPU, memory và PID được giới hạn theo profile private-beta 16 GB.
  • Production image không chứa pip/uv/compiler/git; frontend image không chứa Node/npm.
  • Runtime secret đi qua environment/secret mount, không bake vào image.
  • CI scan toàn bộ Git history, audit dependency dev/runtime, tạo SBOM và chặn HIGH/CRITICAL vulnerability theo policy có kiểm soát.

Ví dụ 3 — Lưu preference có approval

Prompt: “Hãy nhớ từ nay trả lời tôi bằng tiếng Việt.”

  1. Supervisor đề xuất save_user_memory(preference.language, ...).
  2. Middleware ghi pending approval và frontend hiện exact action.
  3. Người dùng bấm Approve.
  4. Graph resume; repository upsert đúng key, tăng revision nếu thay đổi.
  5. memory.updated chỉ chứa key/revision/hash, không raw content.
  6. Lượt sau middleware inject aggregate như untrusted user context.
Nếu bấm Reject: supervisor phải báo không lưu và không đề xuất lại cùng side effect để “thử sửa”.

Ví dụ 4 — Publish strategy lên AI-Trader

Prompt: “Đăng kết quả experiment vừa rồi thành strategy discussion.”

  1. AI-Trader agent nhận experiment/artifact/interpretation IDs thật.
  2. Nội dung gồm market/symbol, research basis, leakage/survivorship/cost/OOS limitation và câu “không phải lời khuyên đầu tư”.
  3. Frontend hiện exact title/content/evidence cho người dùng duyệt.
  4. Approval digest khóa đúng nội dung. Sau approve, publication service reserve idempotency và gọi worker.
  5. Postgres ghi target signal_id; dossier nối publication với approval và evidence.
Không được: thay title/content sau approve; publish “operation” realtime; hoặc publish khi actor chỉ có ai_trader:read.

Ví dụ 5 — Mất mạng giữa run

  1. Browser đã lưu thread ID, active run ID và last event ID trong session.
  2. Mạng rớt sau khi worker accepted nhưng trước khi UI thấy dataset.ready.
  3. Sau reload, frontend reconnect active run stream nếu còn khả dụng.
  4. Frontend gọi product-event replay với after=last_sequence.
  5. Workflow/idempotency ở Postgres ngăn submit side effect mới.
  6. Nếu retention đã mất đoạn cũ, gap=true buộc UI không tuyên bố timeline hoàn chỉnh.

Ví dụ 6 — Provider không có snapshot

AI-Trader market-news trả ok=true, available=false, last_updated_at=null. Câu trả lời đúng là “worker đã kết nối nhưng chưa có cached snapshot; cần refresh và API key nếu muốn lấy dữ liệu mới”. Không nói “AI_TRADER_API_BASE_URL sai”.

Phụ lục D — Checklist vận hành

Trước khi chạy local

  • Đúng Python 3.11, Node 22, uv/npm và Postgres 16.
  • Tạo file local từ .env.example; không commit.
  • Cài extra Qlib/OpenBB nếu cần provider/experiment thật.
  • Kiểm tra port không bị stack cũ chiếm.
  • Chạy migration status/upgrade.

Trước khi chạy private beta

  • OIDC issuer/audience/client/redirect đúng HTTPS.
  • Database password non-default và role riêng từng service.
  • Tenant HMAC, worker token, AI-Trader token và AES key đủ mạnh.
  • Chỉ frontend bind loopback/trusted ingress; worker không public.
  • Named volumes có ownership/backup policy phù hợp với claim một node.
  • Quality, security, container vulnerability và product validation đều green.
  • Chạy live journey gồm approval, reconnect, Evidence và actor isolation.

Khi đánh giá một kết quả quant

  • Dataset revision và manifest verified?
  • Train/valid/test đúng thứ tự và nằm trong coverage/max_test_end?
  • Metric có definition/calculation version/evidence reference?
  • Artifact hash/status/download eligibility hợp lệ?
  • Point-in-time, survivorship, adjustment, calendar, cost và OOS limitation đã nêu?
  • Interpretation có phân biệt historical evidence và investment advice?

Khi xử lý một side effect

  • Actor có permission?
  • Exact arguments đã normalize và hiện cho người dùng?
  • Approval còn hiệu lực và action digest khớp?
  • Idempotency key có gắn đúng action, không reuse cho content khác?
  • Execution result/reference đã ghi; failure có safe code/stage/retryable?

Khi cập nhật tài liệu PDF này

  1. Đổi source baseline/date trên trang bìa.
  2. Đối chiếu entrypoint, topology, route, permission, state machine và config.
  3. Cập nhật HTML, tạo lại PDF bằng lệnh trong docs/pdf/README.md.
  4. Kiểm tra PDF mở được, font tiếng Việt, mục lục/link, bảng không bị cắt.
  5. Review diff và bảo đảm không có secret/runtime data.
